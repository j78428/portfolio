JarviX 介面改版：重構 Design System，讓介面跟得上產品成長

產品快速迭代後，功能變多、複雜度變高，介面卻開始不一致、難以擴充。藉著這次新功能擴充，我重新盤點資訊架構、重構 Design System，進行全盤 UI 改版。

角色
UI / UX Designer
負責內容
新 UI 設計、Design System 建置
資訊架構統整
類型
UI・SaaS・Design System
公司
Synergies

  1. 目標

01目標

產品的發展方向，和當初規劃時已經很不一樣，功能數量與複雜度也大到必須重新規劃。這次全盤 UI 改版有兩個目標：

  • 1因應新功能的擴充讓介面佈局和資訊架構，能持續容納新功能。
  • 2讓 UI 樣式可以快速調整例如企業客戶想要的淺色版本。

02困難

  • 產品快速迭代，設計系統沒有持續跟上，UI 呈現開始不一致。
  • 許多企業客戶希望有淺色版本，但設計和前端都無法快速調整。
  • 新功能越來越多，介面佈局的擴充性開始不足，有些做法也不夠友善。

盤點問題與需求

盤點產品 UI 設計的現況問題，以及未來要規劃的功能需求。

03過程

  • 1重構 Design System提升元件組合彈性與管理性、提升樣式泛用性、重新定義顏色用途。
  • 2優化 UI Layout重新定義間距、定義泛用的框架、減少巢狀色塊的堆疊。
  • 3新舊需求整合整併舊功能與不合時宜的架構、規劃未來的擴充方式。

1. 重構 Design System

A元件狀態與樣式不一致

BEFORE

元件越來越多、狀態定義不完整，沒定義的狀態工程師各自實作；同目的的組件樣式也不同。

AFTER

落實原子設計：先定義字級、色彩、符號、間距、Grid，再補齊每個元件的 Hover、Focus、Active、Disabled 狀態。

看更多畫面（11）

B顏色越加越多，改不動

BEFORE

同一個顏色用在很多地方；遇到配色衝突就新增顏色，最後一堆相似色，也無法支援深淺雙版本。

AFTER

顏色分兩層：原始色彩層＋應用層，並依使用情境分類色票，換色彩風格時規則清楚。

看更多畫面（4）

2. 優化 UI Layout

A什麼都塞進 Dialog

BEFORE

所有設定都用 Dialog，複雜內容放不下、還會兩層疊在一起；步驟式內容讓 Dialog 不是太大就是太小。

AFTER

設定改用頁面呈現，分「步驟類型」和「通用類型」；Dialog 只放輕量的延伸內容。

看更多畫面（8）

B色塊疊太多層

BEFORE

用色塊劃分群組，表格和表單的色塊層層堆疊，造成視覺負擔和空間浪費。

AFTER

第一層資訊不用色塊劃分；設定項目改用分隔線，子項目才用色塊，盡量只留一層。

看更多畫面（5）

3. 新舊需求整合

A導覽架構跟不上產品方向

BEFORE

雙階層 Navigation 的第一層原本要擴充產品模組，但產品已不往這走；加上權限控管，多數人看到的功能更少。

AFTER

整併成單層 Navigation，凸顯重點功能，同時盡量保留原本的操作方式。

看更多畫面（2）

B新功能沒地方放

BEFORE

問句結果要加入大量新功能，舊介面沒有規劃擴充方式，部分功能不容易被發現。

AFTER

盤點現在與未來的功能需求，重新規劃佈局，保留持續擴增的空間。

C三個功能越長越像

BEFORE

「專案釘板、戰情室、應用程式」需要的功能越來越像，造成定位模糊和重複開發。

AFTER

盤點三者的相同與差異，整併到「應用程式」，成為滿足更多情境的核心功能。

04結果

重新盤點資訊架構後，大、小功能之間更好組合。Design System 提升了 UI 的一致性，元件的組合更多元，頁面佈局的擴充性也更好。
