JarviX 介面改版：重構 Design System，讓介面跟得上產品成長

產品快速迭代後，功能變多、複雜度變高，介面卻開始不一致、難以擴充。藉著這次新功能擴充，我重新盤點資訊架構、重構 Design System，進行全盤 UI 改版。

角色
UI / UX Designer
負責內容
新 UI 設計、Design System 建置
資訊架構統整
類型
UI・SaaS・Design System
公司
Synergies
2019 – 2023

目錄

  1. 目標
  2. 困難
  3. 過程
  4. 結果

01目標

產品的發展方向，和當初規劃時已經很不一樣，功能數量與複雜度也大到必須重新規劃。這次全盤 UI 改版有兩個目標：

  • 1因應新功能的擴充讓介面佈局和資訊架構，能持續容納新功能。
  • 2讓 UI 樣式可以快速調整例如企業客戶想要的淺色版本。

02困難

  • 產品快速迭代，設計系統沒有持續跟上，UI 呈現開始不一致。
  • 許多企業客戶希望有淺色版本，但設計和前端都無法快速調整。
  • 新功能越來越多，介面佈局的擴充性開始不足，有些做法也不夠友善。

盤點問題與需求

盤點產品 UI 設計的現況問題，以及未來要規劃的功能需求。

03過程

  • 1重構 Design System提升元件組合彈性與管理性、提升樣式泛用性、重新定義顏色用途。
  • 2優化 UI Layout重新定義間距、定義泛用的框架、減少巢狀色塊的堆疊。
  • 3新舊需求整合整併舊功能與不合時宜的架構、規劃未來的擴充方式。

1. 重構 Design System

BEFORE

A｜產品規模變大，元件和組件的數量也越來越多，管理難度很高：

  • 許多元件的狀態定義不完整，沒定義到的狀態，工程師各自實作，結果都不同。
  • 使用目的一樣的組件，UI 樣式卻不同。

B｜舊的色彩計畫太基礎：

  • 同一個顏色被用在很多地方（底色、邊線），很難單獨調整。
  • 配色邏輯沒有被設計，遇到衝突只能新增顏色，最後出現一堆相似色。
  • 未來要支援深淺雙版本，但色票和實際應用有落差，只能逐頁校對。
AFTER

A｜落實「原子設計」：先完整定義元素和元件，再製作組件。

  • 定義基礎元素：字級、色彩、符號、間距、Layout Grid。
  • 補齊元件狀態：按鈕的 Hover、Focus、Active，輸入元件有值與沒值的 Disabled 狀態。
  • 同一個組件提供更多變化，例如下拉選單可切換多選、單選、次資訊、符號。

B｜重新定義色彩計畫：

  • 顏色分兩層：第一層是原始色彩層，第二層是應用層，從色彩層取色組合。轉換色彩風格時，很清楚有哪些顏色可用、規則是什麼。
  • 依使用情境分類色票。設計 UI 時照使用意圖選色，避免相同顏色混用造成配色衝突。

2. 優化 UI Layout

BEFORE

A｜所有設定類內容都用 Dialog 呈現。遇到複雜的內容，顯示受限、操作體驗也差：

  • 需要次階層設定或再次確認時，得想辦法避免兩個 Dialog 疊在一起。
  • 步驟類的設定內容差異大，Dialog 不是太大就是太小。

B｜多層資訊或多個設定項時，常用色塊劃分群組，色塊疊太多，造成視覺負擔和空間浪費。表格和表單都有這個問題。

AFTER

A｜盤點所有設定畫面，改用頁面呈現，Dialog 只作為頁面的延伸區塊。

  • 設定頁分「步驟類型」和「通用類型」：步驟類型支援需要引導的設定；通用類型只定義 Header，保留最完整的空間給內容。
  • 少數地方仍需要 Dialog，但只放輕量的延伸內容。

B｜重新規劃多層資訊的呈現：

  • 第一層資訊避免直接用色塊劃分，區塊顏色選擇有深淺差異、但不突兀的配色。
  • 設定項目改用分隔線分類，子項目才用色塊搭配表格，盡量只留一層色塊。

3. 新舊需求整合

BEFORE

A｜舊的 Navigation 是雙階層，第一層原本要擴充更多產品模組，但產品已不往這個方向發展；加上權限控管，多數使用者看到的功能更少。

B｜智能分析的問句結果要加入大量新功能，但舊介面沒有規劃擴充方式，部分功能不容易被發現。

C｜「專案釘板、戰情室、應用程式」需要的基礎功能越來越像，使用者希望 A 功能也能用 B 的某個功能，造成功能定位模糊和重複開發。

AFTER

A｜重新設計資訊架構，整併多階層的 Navigation，更能配合產品策略凸顯重點功能。功能位置大幅調整，但盡量保留原本的操作方式，避免使用者不適應。

B｜盤點現在與未來的功能需求，定義功能與顯示之間的互動關係，重新規劃 UI 佈局，並保留持續擴增的空間。

C｜盤點三個功能並分類，列出相同和差異的項目，整併到「應用程式」，成為能滿足更多情境的核心功能。

04結果

重新盤點資訊架構後，大、小功能之間更好組合。Design System 提升了 UI 的一致性，元件的組合更多元，頁面佈局的擴充性也更好。
