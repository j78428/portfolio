01專案概述

電子製造產業 LED 封裝製程預測系統，包含功能有廠區監控看板、製程參數最佳化、生產良率預測...等項目。

此篇主要說明 Dashboard 監控看板部分的功能設計。

  1. 01需求暸解暸解用戶樣貌與作業流程。
  2. 02定義問題與目標釐清實際情境、定義功能目標。
  3. 03設計方案規劃彙整需求功能、設計操作流程。
  4. 04設計與提案介面規劃、設計提案。

02設計需求

  • 1觀看維度需要可彈性來回切換客戶提及目前內部的看板系統，雖然可以從廠區往下 Drilldown 至大線別、小線別和站台，但若要返回上一層，只能從最上層單位（廠區）從頭點下來，無法直接返回上一層，因此要進行交叉比較時，都需要開好幾個瀏覽器分頁作切換瀏覽。
  • 2需要顯示多樣資訊圖表，但頁面不能太長看板內容除了想看到重要的 KPI 資訊（例如：稼動率、良率）和下一階單位項目的運作資訊之外，還希望可以看到過去一段時間不同 KPI 記錄的圖表，而頁面期待可以不需要太長的滾動就可以瀏覽全部的內容。

03資訊架構規劃

功能架構 Sitemap 統整。監控看板需要涵蓋的階層範圍，從最大單位至最小單位為廠區、大產線別、小產線別、站台。

從 Function Map 中可以發現雖然觀看維度不同（例如：廠區、線別），但需要的資訊項目是相同的。

Wireframe 雛形定義頁面內容的資訊架構。

  • 第 1 區塊用於呈現該維度的當日綜合 KPI 統計，例如：統計 A 廠區之下的所有線別當日的綜合 KPI。
  • 第 2 區塊依不同種類 KPI 顯示各廠的過去到現在的趨勢，例如：A 廠區之下各線別的稼動率趨勢。
  • 第 3 區塊當前維度底下單位的運作狀況，例如：A 廠區之下的所有線別運作細節資訊。

04Layout 規劃

最終版面規劃結果。左側區塊用於顯示目前階層維度（例如：全部廠區／企業整體）的當日生產 KPI 綜合統計。

趨勢圖表用於暸解下一階各單位的生產表現趨勢。採用 Tab 切換方式以同一區塊作為不同圖表內容顯示，不因圖表種類數量過多就讓版面空間過於擁擠或是顯示過長。

下方區塊顯示下一階各單位的當日生產細節資訊，且會依照上方趨勢圖正在觀看的主題一起變更並呈現相同主題資訊內容。

05User flow 設計

監控看板 Userflow 設計概念。

在當前頁面就可以比較下一階層單位的產能狀況，並且可以往其一單位專注探索下去，例如：從全部廠區總覽，可以比較不同廠區的差異。

點擊「大線別概況」按鈕來實踐 Drilldown 行為，就可以往下暸解該廠區下一階層的大產線別運作總覽。

透過麵包屑不僅可以清楚呈現目前所在的單位層級，還可以透過超連結隨意回到不同階層單位，不需要一直返回上一頁。

後續優化想法

雖然原本的麵包屑，很方便可以切換至不同階層單位做瀏覽，但在同一層之間切換反而要經過的步驟卻比較多。若將 Select box 元件融入當中，透過選單就可以直接切換至同層不同項目的內容，切換起來面向更廣更便利。

看板的 Drilldown 行為可以透過麵包屑直接選擇，或者點擊看板區塊的按鈕，且可以彈性切換。Tab 不僅可以變更顯示不同類型資訊，且可以擴充乘載更多資訊。
