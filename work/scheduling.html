智能排程系統：縮短排產時間，跟上產線的每一次變化

從 JarviX 延伸出的「智能排程」功能模組雛形。目標是縮短生管人員安排生產計畫的時間，並在插單、停機等狀況發生時，快速調整計畫。這篇說明從需求了解到設計提案的過程。

01背景與目標

縮短排產時間，跟上產線的每一次變化

縮短生管人員每次安排生產計畫所花的時間，大幅降低製作成本；同時要能跟上產線隨時的變化（例如插單、停機），調整當前的計畫。

02挑戰

多廠區、計算耗時，還要和既有產品分工

  • 生管人員每次排產都要花大量時間，產線一有變化，就得重新調整計畫。
  • 新功能和公司既有產品 JarviX 的關係要先釐清：誰負責資料管理、排程功能怎麼擴充。
  • 系統要支援多個廠區，每個廠區的資料都不同。
  • 排程模擬需要一定的計算時間。

03解法

從使用情境、流程，一路做到完整 Wireframe

整理功能需求

和專案經理一起討論、收斂客戶的需求，整理出基礎的功能清單。

規劃 Sitemap

釐清商業銷售需求，定義排產功能和產品的關係：以 JarviX 負責資料管理，生產排程則作為額外的擴充模組。

設計 User flow

梳理從預測生產需求到產出排程計畫的操作流程，以及中途發生歧異時的處理流程。

版面規劃①：依廠區劃分資料

系統要支援不同廠區，每個廠區的資料也不同，所以進入主要功能前，先以廠區選單劃分。新增廠區時可以直接設定要串接的資料來源，每個廠區各自管理生產排程和相關設定。

版面規劃②：模擬排產計畫

用步驟條引導，主要功能按鈕固定在上方。第一步是預測未來的生產需求：設定預測時間範圍、歷史資料參考範圍、品項限制等條件；使用者對預測結果有其他想法時，可以直接編輯品項、數量和交付日期。

原本的 User flow 沒有「排程模擬設定」這一步。因為使用者希望能參與部分參數的調整，所以加入這個步驟。

排程模擬需要計算時間，為了提升效率，可以一次設定多組方案（最多 4 組）同時模擬。各方案的好壞以 KPI 差異判斷，右側圖表把方案放在一起比較，並凸顯目前正在看的方案，讓左右資訊互相對應。

版面規劃③：當前採用計畫

採用的計畫保留在「當前採用計畫」頁。甘特圖可以切換顯示維度（例如以週為單位）、hover 看更多資訊、切換精簡或詳細模式；產線有變化時可以重新模擬，過去的採用紀錄也能查閱。

04成果

完成智能排程模組的設計提案

完成「智能排程」功能模組的設計提案：使用情境、功能清單、Sitemap、User flow 與完整 Wireframe，另外也製作了 UI 設計。

提案之後的發展（例如：是否開發上線、客戶的回饋）。
